# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run scrape     # Scrape all banks and sync the investment sources once, then run the pipeline (SCRAPE_ONLY=oneZero,ibkr to limit; SCRAPE_FROM=2026-01-01 to backfill; SHOW_BROWSER=0 headless; SCHEDULE="0 7 * * *" to keep running on cron)
npm run dev        # API (127.0.0.1:4310) + dashboard (http://127.0.0.1:5180)
npm run pipeline   # Re-run classification / reconciliation without scraping (writes no snapshot)
npm run categorize # Scraper categories, then the AI for every merchant still without one (-- --all re-asks every merchant not categorised by a person or the scraper)
npm run reports:reextract -- <id>  # Re-read one stored, applied report through the same checks (identity unchanged, values + stated returns update)
npm run import -- <file>  # Import a report (pension, study fund, statement — PDF/CSV/XLSX/image): AI extraction → holdings, or review in the dashboard
npm run link -- onezero  # One-time One Zero SMS 2FA → saves the ~10-year credentials.idToken into accounts.json
npm run schedule:install # launchd: scrape daily at 07:00, log in data/logs/scrape.log (schedule:uninstall removes it)
npm test           # Vitest unit tests (in-memory SQLite)
npm run typecheck  # API typecheck; web: npm --prefix web run typecheck
```

## Architecture

A read-only money dashboard for one household: bank balances, investments by type, expenses, over time. Everything runs locally; the API binds to 127.0.0.1 only and has no login.

- `src/scraper.ts` — `israeli-bank-scrapers` (patched via `patches/` + patch-package: One Zero's mTLS client certificate, eshaham/israeli-bank-scrapers#1172 — drop the patch once a release includes it; it also adds Otsar Hahayal / Beinleumi-group foreign-currency accounts from the "תיק מט"ח" + "תנועות בחשבון מט"ח" pages as `<account>-<CUR>`, failures leave the ILS scrape intact). Fetches 3 months back (or `SCRAPE_FROM`) + 2 future months, raw rows and scraper categories. Hapoalim OTP is prompted in the terminal (or the UI); One Zero logs in with `credentials.idToken` (`src/link.ts`; the patch also adds the idToken login, sergienko4/israeli-bank-scrapers#576). Every successful result is archived verbatim to `data/raw/<company>/<timestamp>.json` (`src/ingest/archive.ts`). Isracard and Amex use our own `src/scrapers/isracardGroup.ts` instead of the library's: login drives the real login page (`#flip` → `#otpLoginId_ID` / `#cardnum` / `#otpLoginPwd`; the page itself runs ValidateIdDataNoReg → IsRegisterNoReg → performLogonI with reCAPTCHA v3, and only their responses are read; the form is submitted at most once and only when every field holds what was typed); data from the DigitalV3 API on web.isracard.co.il (GetCardList / GetMonthlyBilling / GetTransactionsList, eshaham/israeli-bank-scrapers#1159), mapped to the library's result shape. Shared browser masking in `src/scrapers/browser.ts`.
- `src/sync/` — investment sources (`investments[]` in accounts.json) → `holdings`: IBKR Flex Web Service, EVM wallets via Alchemy, exchanges via ccxt (optional dependency; read-only keys). Each adapter sets `asset_class` (`src/sync/assets.ts`: IBKR STK/ETF/FUND → `stock`, CRYPTO → `crypto`, `CASH.*` → `broker_cash`; coins: fiat → `broker_cash`, the shared `STABLECOINS` set (bridged tickers like USDC.e map to their base) → `stablecoin`, else `crypto`). Opening dates and costs (`src/sync/history.ts`, step 104 `holdings.opened_at` + `cost_basis_source`): IBKR — the position's `openDateTime` (summary row, else its earliest lot), cost = `costBasisMoney` (`broker`); exchanges — Binance trades per held coin as base on its quote markets (USDT, USD, USDC, FDUSD, BUSD, TUSD, BTC, ETH, BNB, EUR, GBP, TRY) and as quote (against held / moved coins and majors), deposits / withdrawals (90-day windows), dust conversions to BNB, and Convert trades (`fetchConvertTradeHistory`, else `GET /sapi/v1/convert/tradeFlow`; 30-day windows from a month before the first deposit / trade; a received coin's cost = what was given in USD, else what was received at market), Kraken the whole ledger (trade legs share a refid; `receive`/`spend` = instant buys; staking / earn rewards at zero cost), costs in USD via Yahoo daily closes, then **average cost** (`averageCost`: a sell takes units at the average; a transfer in has unknown cost → cost null when > 1% of the pool; > 5% more units than the pool is unexplained → null), opened = first buy / deposit after the pool was last empty (`trades`); wallets — the first inbound transfer per asset (`alchemy_getAssetTransfers`, looked up once, kept in the holding), no cost. History is archived as `data/raw/<id>-history/`; a refused endpoint is a warning on the successful run (`source_runs.error`, `lastWarning`), never a failure; a position whose history wasn't read this run keeps its stored values. `holdings.ts` upserts by `source` (`<source id>:<account>`) + symbol, archives what disappeared, and prices each position from its Yahoo symbol when the quote agrees with the source's price (±20%), else keeps the source's price as `manual_price`. Stablecoins are priced like any coin, never assumed to be $1.
- `src/db/` — `schema.ts` (one baseline, `schema_version` 100; a database with any other schema is refused — no upgrade from the old `bank.db`), `connection.ts` (`finance.db` unless `BANK_DB`), `ingestRepo.ts` (saves scraped accounts, `source_runs` — every bank/investment run records one, and a run cut short by exit/SIGINT/SIGTERM is recorded as failed — English source names).
- `src/ingest/` — `normalize.ts` (identity: bank reference + installment number, else md5 + occurrence suffix), `classify.ts` (category from the scraper's own category via `category_aliases`; `kind`), `transfers.ts` (card-bill reconciliation, immediate debit-card charges, own-account transfers).
- `src/analytics/` — `fx.ts` (Bank of Israel daily rates, backfilled per held currency; Yahoo only after BOI's last published day), `quotes.ts` (Yahoo quotes), `investments.ts` (holding valuation), `snapshots.ts` (`daily_snapshots` + bank history backfill; step 108 `account_balance_daily` — per bank account (FX accounts too) the day's native balance and its ILS value at that day's rate, written and backfilled with the bank snapshots of sources that succeeded; the pipeline seeds a bank with no rows at its latest bank snapshot), `summary.ts` (the dashboard's data).
- `src/reports/` — reports without an API (pension, study / provident funds, mutual funds, statements) → holdings. `extract.ts` runs the user's own `claude -p` (subscription: `ANTHROPIC_API_KEY` removed; Opus; `--json-schema`; only `Read`, confined to a temp dir holding just the file; prompts in `prompt.md` / `revise.md`; CSV/XLSX go in as text). `corroborate.ts` (deterministic): identity (provider + type + account number, else name similarity; ambiguous → question), edition (same issuer + as-of → replaces), checks that ask instead of applying (sum ≠ stated total ±1%, > 25% move from a report of the same type, a product of the previous report missing, confidence < 0.8, as-of missing / future). `index.ts`: files in `data/reports/<sha256>.<ext>` (same sha256 = already imported), `report_values` = every value point; a holding `report:<provider>:<account>` is priced at its latest point, with one snapshot per point date (step-held). Answers → one AI revision pass → corroborate again. Products may carry stated `returns` (YTD / 12 / 36 months, %, step 105 `report_values.returns`). `reextractReport` re-reads an applied report keeping its issuer / date / owner and its products (a new product or any check's question → nothing changes).
- `src/categorize/` — fully automatic merchant categories, no questions: spend rows (expense / refund) still without a category, grouped by `merchantKey`; merchants not in `merchant_categories` (step 106; `source` ai | rule) go to the user's `claude -p` (`src/ai/claude.ts`, shared with report extraction: subscription, Sonnet, no tools, `--json-schema`; prompt in `prompt.md`) in batches of ≤ 150, offered only the `expense`-kind categories (so a category never changes a row's kind), with the card's unresolved category as a hint. Rows get `category_source = 'ai'`; manual / scraper categories are never touched. Confidence < 0.5 or an unknown name → `Unknown`, still cached. Before the AI, rules (`rules.ts`, `category_source = 'rule'`, re-applied every run, beat AI answers, never sent to the AI): unexplained card bills on bank accounts → `Credit card (not itemised)`, transfers to people (`העברה ל…`, Bit / PayBox) → `Transfers to people` (both rule-only, never offered to the AI), FX fees → `Bank fees`, an unpaired `רכישה-סחר חוץ` → `Foreign purchases`; a non-spend row loses its automatic category. `npm run categorize -- --unknown` re-asks only merchants left in `Unknown`. Categories are English (step 107 renamed the defaults, Hebrew names kept as `category_aliases`). A scraper category whose merchants all landed in one category is added to `category_aliases`. A missing / failing CLI is logged, never fails the pipeline.
- `src/pipeline.ts` — after every scrape, in order: FX → quotes → categorize → kinds → card bills → immediate card debits → transfers → currency exchanges (`matchCurrencyExchanges`: an FX / foreign-trade outflow paired with the same bank's other-currency inflow, ±3 days, ±3% in ILS) → rule + merchant categories (AI) → snapshots.
- `src/server/` — Fastify: `GET /api/summary?range=`, `/api/integrations` (each source's status from `source_runs`: OK / Failed / Stale (no success in 36 h) / Not configured (credentials empty in accounts.json and never a successful run — a bank logged into by hand counts once it succeeds), last 10 runs, accounts/holdings/value; reports counts), `/api/history?range=&group=type|source`, `/api/expenses?months=` (per month: top-level categories — `none` = uncategorised — and top merchants), `/api/expenses/rows?month=|range=&source=&merchant=|category=` (rows carry the cleaned merchant, account, category, installment n/N), `/api/expenses/breakdown?range=&source=` (`src/analytics/expenses.ts`: one source per card account — this month, last month, next charge = everything charged on the first processed date after today, installments left = payments after the last one charged per plan — plus `bank` for spend paid from bank accounts; the range's months, top categories and merchants, of one source when given), `/api/funds?range=` (`src/analytics/funds.ts`: each fund's value, as-of, liquidity date, growth over the range = value change between the report points bracketing it — else the latest report's stated return for the period closest to the range, marked stated — its printed returns and points), `/api/investments?range=` (every non-fund holding with `openedAt`, gain since opened, price change over the range; totals: gain where the cost is known and the share of value it covers), `/api/cashflow?range=&account=` + `/api/cashflow/rows?month=&account=` (`src/analytics/cashflow.ts`: bank rows per month in / out / net and the range's spend by top-level category, by the expense semantics — `transfer` and `card_payment` are neither, `savings` is its own "moved" figure; balances per bank account from `account_balance_daily`, ILS and native); writes: `POST /api/scrape` and `/api/scrape/otp` (`scrapeJob.ts`, one scrape at a time, in memory); integrations (the only other writes, local Host/Origin only): `GET/POST /api/integrations/config`, `PUT/DELETE /api/integrations/config/:key` (`keepData=false` also deletes its data), `POST /api/integrations/config/:key/disabled`, `POST /api/integrations/test` (one source through the scrape job; saved only on success), `POST /api/integrations/link/onezero/start|code` (`src/integrations/link.ts`, shared with `npm run link`); reports: `POST /api/reports` (multipart; extraction in the background), `GET /api/reports[/:id]`, `POST /api/reports/:id/answers`, `DELETE /api/reports/:id`.
- `web/` — Vite + React 19 + Tailwind 4, shadcn/ui (Radix; `components.json`, `@/` alias, `cn` in `src/lib/utils.ts`, primitives in `src/components/ui/`, themed from the palette in `index.css` — app `muted` = secondary text and `accent` = blue keep their meaning); one fixed colour per source as `--color-src-*` tokens in `index.css`, mapped by `sourceColor` in `colors.ts` (One Zero, Hapoalim, Otsar Hahayal, Isracard, Max, IBKR, Binance, Kraken, Wallets, Reports; anything else the neutral fallback) — Bank lines / pills (an FX account's line is dashed), Expenses sources, Investments, Integrations, shadcn charts over Recharts 3, TanStack Table, lucide-react; English LTR, light. `Layout.tsx` (sidebar: navigation only — Dashboard, Bank, Investments, Funds, a separator, Integrations — and the Synced footer; mobile drawer is a Sheet; top bar: "N to review" chip, ₪/$, Add integration (on Integrations), Add report (Dialog), Refresh + OTP), `Funds.tsx` (`/funds`: one row per fund — growth, YTD / 12M / 36M stated returns, sparkline of its report points), `Investments.tsx` (`/investments`: Value / Gain header, TanStack table; two-line rows below `sm`), `Expenses.tsx` (`/bank/expenses`, the Bank page's Expenses tab — `/expenses` redirects here: a card per source, source pills, monthly bars with the current month highlighted, top categories / merchants → a Sheet of rows), `Bank.tsx` (`/bank`, the Cash flow tab — the tabs sit in the top bar: cash flow chart + account pills, Balance lines (one per account; FX accounts show their native balance too), Months table → month Sheet, Spending by category once any row has one), `Dashboard.tsx` (three cards, each opening its page: Bank — total bank balance, this month's expenses beside last month's (→ `/bank/expenses`); Investments — total value; Funds — total balance), `Integrations.tsx` (`/integrations`: one table, Reports as an "Upload" row), `reports.tsx` (drop zone, review panel), `ui.tsx` (card, segmented toggle, side panel, tooltip, tags, `mask(last4)`).

**Key rules:**
- Transaction `kind` decides what counts: `transfer`, `card_payment` and `savings` are never spend. A bank row like `ויזה`/`כאל` is a `card_payment` only when a scraped card's charges explain it; otherwise it is a debit purchase (expense). Money sent to IBKR / Binance / Kraken / wallet on-ramps / investment houses is `savings` (`matchesInvestment`: the name, or ≥ 6 letters of its start — One Zero cuts descriptions). Buying / selling FX between own accounts (`FX_EXCHANGE_PATTERN`) is `transfer`, one leg or both; a transfer to the account holder themself (the name One Zero shows in "העברה מ- <holder> ל- …") is `transfer`.
- Expenses = `kind = 'expense'` minus refunds, in calendar months; installments count on their charge date (`processed_date`), other spend on the purchase date. Merchants are `merchantKey(description)` (no numbers / card suffixes, `חיוב מ-`, company forms, city tails).
- Snapshots: written at the end of a run only for sources that succeeded in it (a failed source keeps its last snapshot); `as_of` = the source's own data time. Bank bucket = latest `balances` row of each bank account; card balances never count as Bank — unbilled card charges (future `processed_date`) are `cards_owed` (negative). Investment buckets = asset classes (report products: pension, study_fund, provident_fund, mutual_fund (קרנות נאמנות), deposit, other; brokerage → stock).
- Funds: for display, pension, study, provident and mutual funds are one top-level type `funds` (`topType` in `summary.ts`: allocation, chart Type stack, holdings and sidebar groups); the stored asset class stays and is shown as a grey sub-type tag. Only top-level types get colour. A report product is named as printed in the report; `••last4` is added (after the name in a bidi isolate, rendered by `Name` in `ui.tsx`) only when two products share a name.
- Bank history: from the movements' `runningBalance` + `valueDate` (exact; One Zero), else walked back from the latest balance over posted rows (fills only missing days).
- A missing exchange rate is flagged and the value left out — never 1:1.
- History by day carries each source's latest snapshot forward; a source counts only from its first snapshot. A range's change is "—" for a bucket whose sources weren't snapshotted by the range start.
- Hebrew regexes can't use `\b` (JS word boundaries are ASCII-only) — use explicit lookaheads. Hebrew matchers stay: they read Hebrew bank data.

**Configuration:**
- `accounts.json` (git-ignored; `ACCOUNTS_FILE` overrides): `accounts[]` with `companyId` and `credentials`; `investments[]` (`type`: `ibkr` / `wallets` / `exchange`); any entry may carry `owner` (display only, not a secret, set from the Integrations editor; an edit that types no credential leaves empty ones alone). Owners are derived at read time (`src/analytics/owners.ts`): an integration's accounts and holdings inherit its owner by source id; a report product shows the owner printed on its latest report (`report_values.owner`, corrected via `PUT /api/reports/:id/owner`). Only the first name is shown, faint: sidebar second line, Holdings column (subtitle on mobile), Accounts card, Integrations column. All secrets live in this one file. Editable from the Integrations page (`src/integrations/manage.ts`): every write backs the file up to `data/backups/accounts-<time>.json` (`BACKUPS_DIR` overrides) and keeps both at chmod 600; listings return only filled + `••••1234`; a blank field keeps the value; `disabled: true` keeps an entry but skips it in every run.
- Ports: `PORT` (API, 4310) and `WEB_PORT` (web, 5180).
